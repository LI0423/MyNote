# AgenticRAG

本质上是把“检索增强生成”从一次流水线，升级为“可规划、可迭代、可用工具、可自我校验”的智能体工作流。

传统RAG：query -> topK检索 -> 把片段塞进prompt -> 生成答案

AgenticRAG：目标 -> 计划 -> 多轮检索/工具调用 -> 证据校验 -> 组织输出 -> 追踪可追溯来源

## 为什么需要Agentic RAG

### 传统RAG问题

- 问题拆不对：复杂问题需要分解、多跳检索（multi-hop），一次topK往往不够。
- 证据不够硬编：检索不到时，模型容易补全。
- 检索策略单一：只做向量topK，碰到编号/专名/报错信息很吃亏。
- 上下文装配粗糙：把相似度高的片段一次塞进去，反而稀释关键信息。
- 无法自我纠错：答错了也不会反思“没召回”还是“召回了但没用对”。

## Agentic RAG核心组成

### 任务理解与规划（Planner）

- 判断问题类型：事实查找/过程操作/比较分析/需要多来源作证/时效性强。
- 生成子问题：把复杂问句拆成可检索的子目标
- 选择策略：先关键词（BM25）还是向量？要不要时间过滤？要不要先查定义再查细节？

通常会生成一个“计划”：

- 子问题列表
- 每个子问题对应的检索/工具策略
- 停止条件（找到足够证据就停）

### 检索执行器（Retriever Orchestrator）

- 向量检索（semantic）
- 关键词/BM25（lexical）
- Hybrid（融合）
- 多库路由（按领域/权限/版本）
- 多粒度（段落/小节/文档摘要）

并且支持多轮检索：第一轮拿到线索 -> 重写query -> 第二轮追踪更精确证据。

### 工具调用（Tools）

Agentic RAG不局限于“查向量库”，还会用工具补强证据：

- 数据库/知识库查询
- API（工单、监控、日志、配置中心等）
- 代码搜索、文档站点搜索
- 计算器/表格/执行环境（算指标、做聚合）
- 甚至“结构化提取器”（把表格/长文提炼成要点）

### 证据评估与重排（Verifier/Reranker）

- cross-encoder rerank（对topN重排）
- 证据一致性检查：多片段是否相互矛盾？是否过期？
- 覆盖度检查：是否回答了所有子问题？
- 引用对齐：每个结论是否能指到具体片段

### 上下文装配与写作（Context Builder + Generator）

- 去重、合并相邻chunk
- 用MMR保持多样性
- 按结构组织：定义 -> 步骤 -> 注意事项 -> 示例 -> 边界条件
- 生成时强制“带引用输出”或“逐条结论-证据映射”

### 记忆与反思

- 短期记忆：当前任务的中间结果（子问题、已检索内容、候选结论）
- 长期记忆：用户偏好、常用库、历史回答、失败案例模式
- 反思/自我纠错：如果证据不足或矛盾，回到“规划/检索”继续迭代

## 经典流程

1. 分类：这问题是单跳还是多跳？是否需要实效性？是否需要精确匹配实体？
2. 分解：拆成2～6个子问题（越多越慢，越少越不够）
3. 第一轮召回：Hybrid（BM25+向量） -> topK
4. 读证据：抽取关键实体/术语/版本号/限制条件
5. 查询改写：把抽取出来的实体塞回query，做第二轮更精准检索
6. 重排与过滤：rerank + metadata过滤（版本/权限/时间）
7. 验证：
   1. 是否每条结论都有证据？
   2. 证据之间是否冲突？
   3. 是否覆盖所有子问题？
8. 组装输出：把证据按结构组织成答案
9. 停止/继续：
   1. 若不足：回到步骤3或5
   2. 若足够：结束

这是一个带停止条件的闭环系统，而不是一次性pipeline。

## 单跳检索（Single-hop Retrival）和多跳检索（Multi-hop Retrival）

回答一个问题时，是否需要一次检索就能拿到完整证据，还是经过“中间推理 -> 再检索”的多轮过程。

### 什么是“跳（hop）”

一次hop = 一次“检索 + 利用结果继续推理”的动作。基于当前问题或中间结论，发起一次新的、语义上不同的检索。

### 单跳检索（Single-hop Retrieval）

问题本身能直接构造一个查询，只需一次检索，就能找到完整答案的证据。

用户问题 -> 一次检索（向量/BM25/Hybrid）-> 命中直接答案 -> 生成

典型特征：

- 问题是原子化的
- 证据是集中在同一段/同一文档
- 不需要先知道A，再去查B

### 多跳检索（Multi-hop Retrival）

问题不能一次性直接检索到答案，必须依赖中间信息，逐步构造新的查询。

用户问题 -> 第一跳：检索A（基础信息） -> 推理/抽取关键线索 -> 第二跳：基于新线索B -> 必要时更多跳 -> 综合答案

后一次检索依赖前一次检索的结果

### 多跳问题常见模式

1. 依赖型
2. 约束型
3. 组合型
4. 排查/诊断型
